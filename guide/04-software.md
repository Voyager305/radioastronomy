# 04. Программное обеспечение (Linux на ноутбуке)

← [Оборудование](03-equipment.md) · [Оглавление](../README.md) · Далее: [Первые наблюдения →](05-first-observations.md)

---

Базовый сценарий руководства: **Linux на небольшом ноутбуке** — у антенны или на рабочем столе. Windows и macOS не требуются.

## Задачи программного обеспечения

1. Отображение «живого» спектра.
2. Запись IQ/спектра на диск.
3. Усреднение и построение профиля линии.
4. В дальнейшем — автоматизация наблюдений.

Осваивать всё сразу не требуется.

## Какой дистрибутив Linux выбрать

| Вариант | Когда применять |
|---------|-------------|
| **Fedora** (Workstation или KDE) | Долгосрочный выбор: свежие пакеты, удобный `dnf` |
| **Ubuntu / Linux Mint** | При потребности в максимуме готовых руководств и простоте |
| **Fedora Astronomy Lab** | Опционально, при параллельной работе с оптикой/KStars; для радио **не обязателен** |
| Лёгкое окружение на старом ноутбуке | XFCE / LXQt / Mate при малом объёме RAM |

Для радиоастрономии достаточно **обычного дистрибутива Linux**. Astronomy Lab добавляет KStars, INDI и научный Python — это удобное дополнение, но RTL-SDR/GQRX всё равно устанавливаются отдельно.

### Требования к ноутбуку

- **Порт USB 2.0** для RTL-SDR (без неисправного пассивного хаба).
- **8 ГБ RAM** комфортно; на 4 ГБ работа возможна без тяжёлого окружения и лишних вкладок.
- SSD вместо старого HDD — заметно удобнее.
- Исправная батарея: для проверок шума БП удобно работать **от батареи**.
- Мощный CPU не требуется: для RTL-SDR и усреднения спектра достаточно старого i5 или даже приемлемого i3.

Ноутбуки прежних поколений (X220/X230/T440 и аналоги) — распространённый и обоснованный выбор для полевого журнала.

## Рекомендуемый порядок освоения

```text
1) rtl_test → GQRX или SDR++      → визуальное понимание спектра
2) Запись спектра / IQ            → сохранение данных
3) Python (numpy/matplotlib)      → усреднение
4) GNU Radio / скрипты HI         → при упоре в ручной труд
```

## Быстрый старт на Fedora

```bash
sudo dnf update
sudo dnf install rtl-sdr gqrx

# далее по потребности
sudo dnf install sdrpp gnuradio python3-numpy python3-scipy python3-matplotlib
```

Имена пакетов немного различаются между релизами. Если пакет не найден:

```bash
dnf search gqrx
dnf search rtl-sdr
dnf search sdrpp
```

### Ubuntu / Debian-подобные

```bash
sudo apt update
sudo apt install rtl-sdr gqrx-sdr
# по потребности:
sudo apt install gnuradio python3-numpy python3-scipy python3-matplotlib
```

## Права доступа к USB (чтобы не запускать всё через sudo)

После установки `rtl-sdr` обычно появляются udev-правила. Если `rtl_test` сообщает об ошибке доступа:

```bash
# типичный путь: добавление в группу plugdev (название зависит от дистрибутива)
groups
sudo usermod -aG plugdev "$USER"
# иногда требуется группа dialout
sudo usermod -aG dialout "$USER"
```

После этого следует **завершить сеанс и войти снова** (либо перезагрузиться).

Проверка оборудования:

```bash
rtl_test
```

Если идёт поток отсчётов без потока сообщений `lost samples` и ошибок USB — приёмник исправен.

**Blog V4 (тюнер R828D):** если устройство не открывается, следует установить свежий `rtl-sdr` или сборку с поддержкой RTL-SDR Blog V4 — старые пакеты иногда поддерживают только классический R820T2.

Полезные команды:

```bash
rtl_eeprom          # информация о модуле (запись выполнять осторожно)
rtl_test -t         # быстрая проверка
```

## GQRX — основной интерфейс для начального уровня

В GQRX:

1. Device: RTL-SDR (или через Soapy/Osmocom — в зависимости от сборки).
2. Sample rate: начать с **1.8–2.4 MSPS**; на слабом ноутбуке ниже.
3. Gain: сначала умеренно, затем вручную.
4. Frequency correction (PPM): подбирается по известному сигналу.

Базовые настройки:

| Параметр | С чего начать |
|----------|----------------|
| Device | RTL-SDR |
| Sample rate | 2.048 MSPS или ниже на слабом CPU |
| RF Gain | вручную, без постоянного клиппинга |
| PPM | подобрать и записать |

Если GQRX работает неустойчиво, устанавливается **SDR++** (`sdrpp`) или CubicSDR. Логика та же: частота, gain, спектрограмма, запись.

## Калибровка частоты (PPM)

Частота RTL-SDR немного уходит. Для FM это несущественно, для HI уже критично.

Порядок подбора PPM:

1. Найти известный узкий сигнал (сильную станцию или узкую помеху с известной частотой).
2. Подстраивать PPM до совпадения маркера.
3. Записать значение в заметки сессии.

Перед сессией HI модулю дают прогреться **10–20 минут**: после включения частота может смещаться.

## Запись данных: что сохранять

| Формат | Плюсы | Минусы |
|--------|-------|--------|
| Снимок спектрограммы | Просто | Малопригоден для анализа |
| CSV / текстовый спектр | Удобен для Python | Зависит от ПО |
| IQ (raw/wav) | Максимальная гибкость | Большой объём на малом диске |

На ноутбуке место ограничено: для первой линии HI достаточно **серии усреднённых спектров** и метаданных, а не суток сырого IQ.

Метаданные сессии:

- дата/время (**UTC**);
- центральная частота;
- полоса / sample rate;
- усиление;
- PPM;
- направление антенны (азимут/высота хотя бы приблизительно);
- питание от батареи или от сети.

## GNU Radio — когда переходить

GNU Radio целесообразен, если:

- требуется собственный спектрометр/интегратор;
- нужно потоковое усреднение в течение часов;
- удобна работа с блок-схемами.

Не в первый вечер. Сначала сигнал регистрируется визуально в GQRX/SDR++.

Идея flowgraph:

```text
RTL-SDR Source → Stream to Vector
→ FFT → Complex to Mag² → Integrate/Average → File/UI sink
```

На слабом ноутбуке не следует без необходимости увеличивать FFT и sample rate.

## Полевой режим на ноутбуке с Linux

1. Питание от **батареи** на сравнительных проверках шума.
2. Отключение неиспользуемых Wi‑Fi/Bluetooth при поиске собственного RFI (в рамках эксперимента).
3. Перевод ноутбука в режим без засыпания на время усреднения.
4. Запись данных на SSD/`~/radio-data/` с периодическим копированием на внешний носитель.
5. Внешний монитор не обязателен: важнее стабильный USB и меньшее число фоновых программ.

Тот же стек Linux впоследствии легко переносится на Raspberry Pi у антенны.

## Частые проблемы на Linux

| Симптом | Что проверить |
|---------|----------------|
| `Failed to open rtlsdr` | udev/группы, занятый процесс (уже открыт `gqrx`), USB |
| Device not found | кабель, порт, `dmesg \| tail`, другой порт |
| `lost samples` / пропуски | снизить sample rate, закрыть лишнее, другой USB |
| Спектрограмма белая/чёрная | усиление и масштаб |
| Полосы-пики | RFI в помещении, шум USB/БП; сравнить питание от батареи и от сети |
| Частота смещена | PPM, прогрев, неверная центральная частота |

Определение процесса, занявшего модуль:

```bash
sudo lsof | grep -i usb
# либо закрыть все SDR-программы и повторить rtl_test
```
