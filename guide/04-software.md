# 04. Программы (Linux + ThinkPad / нетбук)

---

Базовый сценарий этого гайда: **Linux на небольшом ноутбуке (ThinkPad / нетбук)** у антенны или на столе. Windows и macOS не нужны.

## Задача ПО

1. Увидеть «живой» спектр.
2. Записать IQ/спектр на диск.
3. Усреднить и посмотреть профиль линии.
4. Позже — автоматизировать наблюдения.

Новичку не нужно осваивать всё сразу.

## Какой Linux ставить

| Вариант | Когда брать |
|---------|-------------|
| **Обычная Fedora** (Workstation или KDE) | Хороший выбор «на года», свежие пакеты, удобный `dnf` |
| **Ubuntu / Linux Mint** | Если хочется максимум готовых гайдов и простоты |
| **Fedora Astronomy Lab** | Опционально, если параллельно оптика/KStars; для радио **не обязательна** |
| Лёгкий DE на старом ThinkPad | XFCE / LXQt / Mate, если мало RAM |

Для радиоастрономии хватает **обычного Linux**. Astronomy Lab даёт KStars, INDI, научный Python — приятный бонус, но RTL-SDR/GQRX всё равно ставятся отдельно.

### Что важно в ThinkPad / нетбуке

- **USB 2.0 порт** для RTL-SDR (без дохлого пассивного хаба).
- **8 ГБ RAM** комфортно; на 4 ГБ тоже можно, но без тяжёлого DE и лишних вкладок.
- SSD вместо старого HDD — заметно приятнее.
- Нормальная батарея: для тестов на шум БП удобно работать **от батареи**.
- Не гонись за мощным CPU: для RTL-SDR и усреднения спектра хватит старого i5 / даже нормального i3.

Старые X220/X230/T440 и аналоги — частый и здравый выбор для полевого лога.

## Рекомендуемый порядок освоения

```text
1) rtl_test → GQRX или SDR++     → глазами понять спектр
2) Запись спектра / IQ            → сохранить данные
3) Python (numpy/matplotlib)      → усреднение
4) GNU Radio / скрипты HI         → когда упрёшься в ручной труд
```

## Быстрый старт на Fedora

```bash
sudo dnf update
sudo dnf install rtl-sdr gqrx

# дальше по желанию
sudo dnf install sdrpp gnuradio python3-numpy python3-scipy python3-matplotlib
```

Имена пакетов чуть плавают между релизами — если чего-то нет:

```bash
dnf search gqrx
dnf search rtl-sdr
dnf search sdrpp
```

### Ubuntu / Debian-подобные

```bash
sudo apt update
sudo apt install rtl-sdr gqrx-sdr
# по желанию:
sudo apt install gnuradio python3-numpy python3-scipy python3-matplotlib
```

## Права на USB (чтобы не запускать всё через sudo)

После установки `rtl-sdr` обычно появляются udev-правила. Если `rtl_test` ругается на доступ:

```bash
# типичный путь: добавить себя в группу plugdev (название зависит от дистрибутива)
groups
sudo usermod -aG plugdev "$USER"
# иногда нужна группа dialout
sudo usermod -aG dialout "$USER"
```

Потом **выйти из сессии и зайти снова** (или перезагрузка).

Проверка железа:

```bash
rtl_test
```

Если идёт поток сэмплов без шквала `lost samples` / ошибок USB — приёмник жив.

**Blog V4 (тюнер R828D):** если устройство не открывается, поставь свежий `rtl-sdr` или сборку с поддержкой RTL-SDR Blog V4 — старые пакеты иногда знают только классический R820T2.

Полезные команды:

```bash
rtl_eeprom          # инфо о стике (осторожно с записью)
rtl_test -t         # быстрый тест
```

## GQRX — основной интерфейс новичка

В GQRX:

1. Device: RTL-SDR (или через Soapy/Osmocom — как предложит твоя сборка).
2. Sample rate: начни с **1.8–2.4 MSPS**; на слабом нетбуке лучше ниже.
3. Gain: сначала умеренно, потом вручную.
4. Frequency correction (PPM): подбери по известному сигналу.

Базовые настройки:

| Параметр | С чего начать |
|----------|----------------|
| Device | RTL-SDR |
| Sample rate | 2.048 MSPS или ниже на слабом CPU |
| RF Gain | вручную, без постоянного клиппинга |
| PPM | подобрать и записать |

Если GQRX капризничает — ставь **SDR++** (`sdrpp`) или CubicSDR. Логика та же: частота, gain, водопад, запись.

## Калибровка частоты (PPM)

RTL-SDR чуть «плывёт» по частоте. Для FM это терпимо, для HI уже раздражает.

Как подобрать PPM:

1. Найди известный узкий сигнал (сильная станция/узкая помеха с известной частотой).
2. Подкручивай PPM, пока маркер совпадёт.
3. Запиши значение в заметки сессии.

Для HI дай стику прогреться **10–20 минут**: частота может уехать после старта.

## Запись данных: что сохранять

| Формат | Плюсы | Минусы |
|--------|-------|--------|
| Скрин водопада | Просто | Плохо для науки |
| CSV/текстовый спектр | Легко в Python | Зависит от ПО |
| IQ (raw/wav) | Максимум гибкости | Много места на маленьком диске |

На нетбуке место ограничено: для первой HI-линии достаточно **серии усреднённых спектров** + метаданных, а не суток сырого IQ.

Метаданные сессии:

- дата/время (**UTC**);
- частота центра;
- полоса / sample rate;
- усиление;
- PPM;
- куда смотрела антенна (азимут/высота хотя бы грубо);
- от батареи или от сети.

## GNU Radio — когда пора

Иди в GNU Radio, если:

- хочешь свой спектрометр/интегратор;
- нужно потоково усреднять часами;
- нравится собирать блок-схемы.

Не в первый вечер. Сначала поймай сигнал глазами в GQRX/SDR++.

Идея flowgraph:

```text
RTL-SDR Source → Stream to Vector
→ FFT → Complex to Mag² → Integrate/Average → File/UI sink
```

На слабом ThinkPad не раздувай FFT и sample rate без нужды.

## Полевой режим на Linux-ноуте

1. Питание от **батареи** на сравнительных тестах шума.
2. Отключи ненужный Wi‑Fi/Bluetooth, если ловишь свой RFI (эксперимент).
3. Поставь ноут в режим «не засыпать», пока идёт усреднение.
4. Пиши данные на SSD/`~/radio-data/`, периодически копируй на флешку.
5. Внешний монитор не обязателен: важнее стабильный USB и меньше фоновых программ.

Позже тот же Linux-стек легко переносится на Raspberry Pi у антенны.

## Частые проблемы на Linux

| Симптом | Что проверить |
|---------|----------------|
| `Failed to open rtlsdr` | udev/группы, занятый процесс (`gqrx` уже открыт), USB |
| Device not found | кабель, порт, `dmesg \| tail`, другой порт |
| `lost samples` / провалы | снизить sample rate, закрыть лишнее, другой USB |
| Водопад белый/чёрный | gain и масштаб |
| Полосы-иголки | RFI дома, шум USB/БП; сравни батарею vs сеть |
| Частота «не туда» | PPM, прогрев, неверный center |

Узнать, кто занял стик:

```bash
sudo lsof | grep -i usb
# или просто закрой все SDR-программы и повтори rtl_test
```
